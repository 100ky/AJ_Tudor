Přesto se při extenzivním využívání konverzačních modelů objevují dva protichůdné, avšak fundamentálně propojené problémy: model má na jedné straně tendenci neustále se vracet ke stejným třem tématům, což vyvolává uživatelskou frustraci a repetitivní nudu, a na straně druhé nedokáže udržet souvislou nit konverzace, čímž dochází k chaotickému přeskakování mezi nesouvisejícími okruhy.Tato analýza se do hloubky zabývá příčinami těchto jevů na úrovni architektury neuronových sítí a mechanismu pozornosti. Tento úpadek není dán nedostatečným počtem parametrů modelu, nýbrž strukturálním defektem v tom, jak standardní mechanismus pozornosti (self-attention) přistupuje k nestrukturované historii konverzace.Mechanismus pozornosti přiřazuje váhu všem tokenům v aktivním kontextovém okně. S každou další replikou se kontext plní nejen relevantními informacemi, ale také šumem, redundantním textem a dřívějšími chybami. V multi-turn dialozích toto vede ke třem specifickým formám degradace. První formou je znečištění pozornosti (attention pollution), kdy se rané faktické chyby nebo halucinace modelu propagují napříč celou konverzací, protože jim model neustále věnuje část své výpočetní kapacity. Druhou formou je ředění pozornosti (attention dilution), což je stav, kdy jsou vysoce důležité systémové instrukce – například pokyn, aby tutor nehrál roli detektiva a nekladl pouze otázky – postupně přehlušeny objemem vygenerovaného textu. Třetím projevem je sémantický drift (attention drift), kdy se původní cíl konverzace postupně vytrácí a model reaguje pouze na nejrecentnější, avšak sémanticky okrajové tokeny, což vede k náhlým a nepřirozeným skokům v tématu.Kromě těchto forem degradace čelí konverzační systémy problému pozičního zkreslení. Modely mají tendenci alokovat neúměrné množství pozornosti na počáteční tokeny kontextu (tzv. "attention sinks") a naopak ignorovat střední část konverzace (efekt "lost-in-the-middle"). Pokud je profil studenta obsahující seznam dřívějších chyb fixně ukotven na začátku systémového promptu, stává se tento profil silným "attention sinkem". LLM tuto trvalou přítomnost sady chyb vnímá jako primární direktivu. Namísto přirozeného rozvoje konverzace se model začne zacyklovat v tzv. vyšetřovacím módu, kdy se neustále snaží tvořit situace, ve kterých by mohl studenta z těchto specifických chyb otestovat. Tradiční architektury pouze přidávají nové záznamy o chybách (například prostřednictvím stávajícího MemoryManagerAgent), což vede k lineárnímu nárůstu položek v proměnné recurringErrors. Ponechání těchto záznamů v paměti modelu způsobuje, že systém vykazuje sémantickou slepotu vůči pokroku uživatele.Ebbinghausova křivka a konceptuální odnaučováníPro efektivní správu paměti tutora je nezbytné aplikovat mechanismy inspirované kognitivní psychologií, konkrétně Ebbinghausovou křivkou zapomínání. Hermann Ebbinghaus v roce 1885 demonstroval, že paměťová stopa bez opakování exponenciálně klesá. Tento pokles lze matematicky vyjádřit vzorcem $R = e^{-t/S}$, kde $R$ představuje míru retence (vybavení), $t$ je čas uplynulý od poslední expozice a $S$ je stabilita paměťové stopy. V kontextu umělé inteligence se tento princip adaptuje pro navrhování systémů rozloženého opakování (Spaced Repetition Systems) a dynamického sledování znalostí (Knowledge Proficiency Tracing).Aplikace Ebbinghausova modelu na AI tutora znamená, že paměť systému nesmí být statická. Paměťové záznamy o chybách studenta musí podléhat časovému úpadku, pokud nejsou znovu pozorovány. Rámce jako TASA (Teaching According to Students' Aptitude) prokazují, že integrace křivky zapomínání do profilu studenta umožňuje generovat kontextově mnohem přiměřenější otázky a vysvětlení. V praxi to znamená, že pokud MemoryManagerAgent detekuje v transkriptu správné použití dříve chybného jevu (např. student správně použije minulý čas nepravidelného slovesa), musí dojít k cílenému snížení váhy tohoto jevu nebo k jeho úplnému smazání z aktivního kontextu.Tento mechanismus lze formalizovat v rámci paradigmatu "Memory-as-Action" (MemAct). MemAct definuje správu kontextu nikoliv jako externí fixní pravidlo, ale jako sadu operací pro úpravu pracovní paměti, které se systém učí provádět, typicky operace typu "prune" (ořezat) a "write" (zapsat). Zatímco plně autonomní MemAct spoléhá na zpětnovazební učení k provádění těchto akcí v reálném čase, pro produkční aplikace založené na volání API je mnohem stabilnější přístup označovaný jako Deterministický paměťový rámec (Deterministic Memory Framework).       'required': ['topicSummary', 'fluencyScore', 'estimatedLevel', 'totalErrors', 'briefing', 'resolvedErrors', 'vocabulary', 'errors']
    };
  }

  static String _buildProfileContext({
    String? recurringErrors,
    String? vocabulary,
    String? recentTopics,
    String? memoryBriefing,
  }) {
    final parts = <String>[];
    if (memoryBriefing != null && memoryBriefing.isNotEmpty) {
      parts.add('KONTEXT Z MINULÉ LEKCE A SEBE-REFLEXE (PAMĚŤ):\n$memoryBriefing');
    }
    if (recurringErrors != null && recurringErrors.isNotEmpty && recurringErrors != '[]') {
      parts.add('AKTUÁLNÍ OPRAVOVANÉ CHYBY STUDENTA (Nezmiňuj je, ale organicky je sleduj):\n$recurringErrors');
    }
    if (vocabulary != null && vocabulary.isNotEmpty && vocabulary != '[]') {
      parts.add('ZVLÁDNUTÁ SLOVÍČKA:\n$vocabulary');
    }
    if (recentTopics != null && recentTopics.isNotEmpty && recentTopics != '[]') {
      parts.add('ZÁJMY STUDENTA:\n$recentTopics');
    }
    return parts.isEmpty ? '' : 'DATOVÝ PROFIL STUDENTA:\n${parts.join('\n\n')}';
  }

/// Agent zodpovědný za post-procesing, detekci sentimentu a Memory Pruning (MemAct).
class MemoryManagerAgent {
  final Ref _ref;

  MemoryManagerAgent(this._ref);

  Future<void> analyzeSession(int sessionId) async {
    L.i('Zahajuji analytickou relaci a prořezávání paměti (Memory Pruning) pro session $sessionId...');
    
    final repo = _ref.read(sessionRepositoryProvider);
    final gemini = _ref.read(geminiAnalysisClientProvider);
    
    if (gemini == null) return;

    try {
      final transcripts = await repo.getTranscripts(sessionId);
      if (transcripts.isEmpty) return;

      final chatHistory = transcripts.map((t) => '${t.speaker}: ${t.content}').join('\n');
      final wrappedHistory = '<transcript>\n$chatHistory\n</transcript>';

      final userProfile = await repo.getUserProfile();
      final previousBriefing = userProfile?.memoryBriefing;
      
      // Detekce validity analýzy vzhledem k délce konverzace
      final userMessagesCount = transcripts.where((t) => t.speaker == 'user').length;
      final isTooShort = userMessagesCount < 2;

      final analysisResult = await gemini.sendMessage(
        wrappedHistory,
        systemPrompt: SystemPromptBuilder.buildAnalysisPrompt(previousBriefing: previousBriefing),
        responseSchema: SystemPromptBuilder.getAnalysisResponseSchema(),
      );
      
      final data = jsonDecode(analysisResult);

      await repo.updateSessionAnalysis(
        sessionId: sessionId,
        topicSummary: data['topicSummary'] ?? 'Bez popisu',
        fluencyScore: (data['fluencyScore'] ?? 0.0).toDouble(),
        totalErrors: (data['totalErrors'] ?? 0).toInt(),
      );

      // --- ALGORITMUS ODNAUČOVÁNÍ (Memory Pruning) ---
      // Extrahujeme seznam chyb, které student přestal opakovat.
      if (data['resolvedErrors'] != null && data['resolvedErrors'] is List) {
        final List<String> resolved = List<String>.from(data['resolvedErrors']);
        if (resolved.isNotEmpty) {
          L.i('Detekováno zlepšení studenta. Aplikuji Ebbinghausův úpadek a prořezávám chyby: $resolved');
          
          // Repozitář provede vyhledání a odstranění těchto jevů z opakujících se chyb
          // čímž se efektivně uvolní kapacita kontextového okna a zabrání zacyklení
          await repo.pruneResolvedErrors(resolved); 
        }
      }

      // --- INTEGRACE FRUSTRACE A SEBE-REFLEXE ---
      if (!isTooShort) {
        String finalBriefing = data['briefing'] ?? '';
        final tutorFeedback = data['tutorFeedback'];
        
        // Zřetězení analytického briefingu s kritikou chování AI
        if (tutorFeedback != null && tutorFeedback.toString().isNotEmpty) {
           finalBriefing += '\n\nKRITICKÁ SEBE-REFLEXE (Self-Correction pro tutora na příště): $tutorFeedback';
        }
        await repo.updateUserMemory(finalBriefing);
      }
      
      if (data['estimatedLevel'] != null) {
        await repo.updateTargetLevel(data['estimatedLevel'].toString().toUpperCase());
      }
      
      if (data['vocabulary'] != null && data['vocabulary'] is List) {
        await repo.updateUserVocabulary(List<String>.from(data['vocabulary']));
      }

      // Logování nových chyb z aktuální relace
      if (data['errors'] != null && data['errors'] is List) {
        final List<String> newErrors = [];
        for (var err in data['errors']) {
          await repo.addErrorLog(
            sessionId: sessionId,
            errorType: err['type'] ?? 'grammar',
            userSaid: err['userSaid'] ?? '',
            correctForm: err['correctForm'] ?? '',
            explanation: err['explanation'] ?? '',
          );
          newErrors.add('Řekl: "${err['userSaid']}", správně: "${err['correctForm']}"');
        }
        if (newErrors.isNotEmpty) {
          await repo.updateUserRecurringErrors(newErrors);
        }
      }

      // Spuštění prediktivního generování nových scénářů
      _ref.read(scenarioPlannerAgentProvider).planScenarios();

    } catch (e, stack) {
      L.e('Kritická chyba při strukturované analýze session', e, stack);
    }
  }
}
